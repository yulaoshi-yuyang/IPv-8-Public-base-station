# ADR 0002 — 观测底座：in-band 回执帧与质量信号面

## 背景

09-21 议程裁决四件事中的后两件——`--mp` alt 路径熔断、FEC 自适应启停——
共享同一个前置件：**数据面质量信号**。现状没有这件东西：外层无逐包 ACK，
在线活性只有 ping8 60s / resolver 20s 心跳，与数据路径无关、无丢包率信号；
mp 双发是否在白花钱、FEC 该不该开，当前都无数据可依。

裁决双过后，信号"从哪来"仍未定（候选 A 旁路探针 / 候选 B in-band 回执）。
本 ADR 收口候选选择与信号面的形态。

## 决定了什么

1. 采**候选 B：in-band 回执帧**。新帧 `FrameType::Receipt = 7`，
   帧体为 124B 定长报告，走与 Data 相同的 AEAD 密封（aad 空、方向分离密钥天然适用），
   周期 200ms，首份立即发。引擎不处理，node 层分流解壳后喂观测器；
   未接线时落到引擎静默丢弃（与 Type=6 FEC 同构，零回归）。
2. 信号生产放新 crate **`ipv8-observe`**：纯函数、零依赖、不做 I/O、时钟注入。
   - 计数法复用隧道既有事实：Data 帧尾计数器明文（防重放所需），128 位图
     稀疏滑动窗 per-SA（≤8 条），产出 expected/seen/dup/resets 与最近收包年龄。
   - 三个计数槽：main / alt / **union**。mp 双发同帧在路径槽各记一份，
     union 做一次去重——熔断按路径槽，FEC 门控只信 union（防双份计账虚抬丢包）。
   - RTT 用 RTCP 式 LSR/DLSR（对端报告 send_ts 回显），不另开时钟协商。
3. 两个滞回判决（防抖动）：
   - **熔断**：连续 3 窗"main 活（年龄≤600ms）且 alt 死透（>1000ms）"→ 停 alt 双发；
     open 态连续 5 窗 alt 活且收包率≥50%（窗口样本≥32）→ 恢复；
     main 也死时**永不熔断**（双断是链路整体问题，不是 alt 单路径故障）。
   - **FEC 门控**：union 丢包率≥30‰ 连续 2 窗开、≤5‰ 连续 5 窗关、中间保持；
     样本<32 冻结，初始关闭。
4. node 是唯一知道路径归属（入站 `from: SocketAddr`）的层，观测器挂 node，
   不进 tunnel 引擎。

## 为什么（考虑过的替代方案）

- **候选 A：旁路探针**（借 IP8N HELLO/ACK 周期探活）：只能给 alt 活性，
  给不出丢包率——FEC 门控无米下锅；邻居流量非常驻、非 per-path，要改造。
  仅过 mp 裁决时它够用；两裁决双过后候选 B 被强制。
- **观测塞进 tunnel 引擎**：tunnel 被迫耦合策略语义；路径归属在 node 层
  （引擎不知道包从哪个 socket 来）；且 shard 路径下明文帧不经过引擎单点，
  观测放 node/独立 crate 才能覆盖全部入口。
- **独立测量协议/探针包**：额外往返流量，探针路径的 NAT 与丢包行为不代表真实数据流。
- **回执不加密**：伪造的健康报告即可操纵对端熔断与 FEC（骗关 FEC / 骗烧双发带宽），
  必须与 Data 同密钥 AEAD，且复用重放/密钥轮换，零新增信任面。
- **可变长 TLV 报告**：为零新增解析复杂度与定长可断言，首版固定 124B；
  扩槽位靠版本号（REPORT_VERSION）不靠变长。

## 什么条件下可以推翻

- 实测回执开销不可接受：理论账约 200B/200ms ≈ 8kbps/方向（3M 链路占 0.27%）；
  若真机实测显著高于此，先调周期，周期调到 1s 仍不可接受则重审形态。
- 高丢包路径上回执帧自身长期不可达，导致判决永久冻结——此时复活候选 A
  作为故障兜底信号，与 B 并存而非替换。
- 数据面帧格式整体改版、帧类型重新编号时，本帧布局一并重评。
