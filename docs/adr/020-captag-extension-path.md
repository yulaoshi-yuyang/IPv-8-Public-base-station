# ADR-020: CapTag 扩容走扩展头索引，而非扩地址

状态: Accepted
关联: protocol-spec §3.3 §3.4 §6.2

## 背景

IPv8+ 地址内 CapTag 只有 16 bit（65536 个能力索引），ANS 能力寻址是
产品核心卖点，索引空间存在耗尽风险。

## 选项

A. 地址扩到 256 bit：直接破坏 40 字节基础头与 128 位不可压缩论证，
   所有已部署解析器报废。
B. 扩展头承载全文 + 地址内置哨兵：CapTag = 0xFFFF 表示"全文见
   SemanticTag 扩展头"，ZoneServer 维护索引。

## 决策

**B**，前提是 §6.2 的未知扩展头跳过规则先进规范（老节点必须能安全
跳过它不认识的 SemanticTag 载荷）。本 ADR 与 ipv8-codec 的
`ExtType::Unknown` 实现同步落地。

## 后果

- CapTag 有效容量实际为 65535 + ∞（全文扩展头无索引上限）。
- Reserved 24 位的用途边界被锁死为"未来非能力字段"，防止有人
  往地址里塞能力数据破坏定长布局。
