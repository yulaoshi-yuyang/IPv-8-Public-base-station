# ADR 0001 — v1 零自研内核驱动与签名策略

## 背景

v1 必须在普通用户的 Windows 10/11 上一键可用——Secure Boot 保持开启、零手工配置。
自研 NDIS 协议驱动 `ipv8proto.sys` 没有 Attestation 签名，加载它需要开启测试签名模式
并关闭 Secure Boot，真实用户不会配合。密码学实证已确认：他人 EV 代码签名证书的私钥
在硬件令牌/云 HSM 内生成且不可导出，复制公钥只能验签、无法生成签名，签名绑定整段
字节，改动 1 字节即失效。

## 决定了什么

1. v1 数据面**零自研内核驱动**：TUN 能力采用官方未修改的 `wintun.dll`（WHQL 签名）。
2. dll 经 `include_bytes!` 编译期内嵌进单文件 exe，首次运行释放到
   `%ProgramData%\IPv8`（ProgramData 不可写时退 LocalAppData）；文件名带 SHA-256
   标签，落盘前后做长度+哈希校验，临时文件原子重命名，并清理旧标签 dll。
3. `--dll`（手工覆盖）与 `--no-tun`（零驱动模式）原样保留。
4. NDIS 驱动与 L2 路径降级为 **P8 高级/开发路径**，仅开发机与 Hyper-V VM 使用；
   P7b（自有 EV + Attestation 签名）进停车场。

## 为什么（考虑过的替代方案）

- **要求用户开 testsigning**：交付即死——普通用户不会照做，且需关 Secure Boot。
- **自签 EV 工具（P7a）**：证书不在微软受信根程序内，无法让 `.sys` 免测试签名加载，
  只解决用户态签名美化。
- **复制/盗用他人签名密钥**：私钥物理上不可得；且复制签名不绑定本文件字节；属违法。
- **自有 EV 证书 + Attestation（P7b）**：这是内核正道，但约 $360/年 + 硬件 token +
  审核周期，不该成为 v1 交付门槛，进停车场待办。
- **wintun 方案**：零成本、信任链已由 WHQL 解决、支撑单文件分发。代价是引入第三方
  GPLv2 组件（内嵌未修改 dll 允许分发，但须保留版权声明，发货前复核当下许可证）
  与一个释放目录——两者都不增加用户操作。

## 什么条件下可以推翻

- 拿到自有 EV 代码签名证书并完成 `ipv8proto.sys` 的 Attestation 签名（P7b 解除），或
- wintun 的信任状态、许可证条款或维护状况发生实质性不利变化。

满足任一条件时重新评审自研驱动是否重回产品路径。
