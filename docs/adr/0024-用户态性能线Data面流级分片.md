# ADR 0024 — 用户态性能线：Data 面流级分片（多核扩展）

> 是什么：把隧道 Data 面拆成 N 个流级分片 worker（用户态多核扩展）；单点引擎拆分后冻结 Data 处理、只留控制面。
> 证据来源：src/core/ipv8-tunnel/src/flow.rs:1-20；src/core/ipv8-tunnel/src/engine.rs:116-118、229-232；src/core/ipv8-tunnel/src/crypto.rs:209-212、320-323；src/core/ipv8-tunnel/src/frame.rs:121-122；src/adapter/wintun-node/src/main.rs:368-371、434-435。
> 抽取日期：2026-10-13（自代码注释抽取，债 1）。口径说明：docs/debt.md 原概括为"内核数据面拒绝"，代码注释原文均为"用户态性能线"，本文以注释为准。

## 背景

Phase 5 实测单线程引擎是吞吐瓶颈（AES 后 7.5 Gbps/核）。要把 Data 面扩展
到多核，同时不能动握手/降级等控制面。

## 决定了什么

1. **Data 面拆成 N 个互不共享密钥状态的 worker 线程**；握手/降级等控制面
   仍归原 Engine。Engine 经 `split_shards` 移交后进入"控制面模式"：单点
   seal/Data 处理一律拒绝（`NotEstablished`），数据面由上层 FlowShards
   接管，握手状态机不受影响（flow.rs:1-5、engine.rs:116-118、229-232）。
2. 分片正确性两根支柱（均在 crypto 层实现）：
   - 发送侧：内层 IP 五元组哈希 → 分片 k → 该流全部帧由 k 的 SA 封装。
     同流同 worker → 计数器严格递增 → nonce 唯一，无需跨线程协调。
   - 接收侧：分片 k 的 SA 轮换步幅 = N（epoch ≡ k mod N），帧头 KeyID 的
     epoch 同余类**免解密**即可路由到对应 worker；跨片帧 `ShardMismatch`
     拒收，绝不串片解密（flow.rs:7-12、crypto.rs:209-212、320-323、frame.rs:121-122）。
3. 部署约束：两端 (N, 套件) 必须人工一致（同 ADR-025 部署配置哲学）；
   N 取值 1..=64，默认 1 = 单点零回归；仅真实 TUN 路径生效，--no-tun
   回显验证件恒单点；错配表现为丢包（非错交付）+ dropped 计数，可诊断
   （flow.rs:17-18、main.rs:368-371、434-435）。
4. 已知限制（与单点 Engine 差异）：仅端点投递语义，多跳转发（fwd /
   RouteTrace 链）不走本路径，需要转发的节点保持单 Engine；帧到达顺序
   不再全局单调（各片独立计数器），IPv8+ 分片组按 frag 同余类路由，
   重组器容忍乱序不受影响（flow.rs:14-20）。
