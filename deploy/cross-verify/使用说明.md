# 这个包是干嘛的？30 秒看懂

你自己写的加密隧道软件（Strata），之前一直在**一台电脑上自己跟自己玩**：
两个假节点在同一台机器上互相发数据包。这说明代码能跑，但说明不了它能在
**真实网络上**跑——万一走公网就崩呢？

这个包就是拿来补这一课的：把测试扔到**两台真电脑**上，走真实网线，
验证加密隧道真能把数据从 A 机送到 B 机。包里是工具 + 一条傻瓜命令。

---

# 先认识你手里这两台机器

| 代号 | 情况 | 打个比方 |
|---|---|---|
| **V 机** | 有公网 IPv6 地址（`2` 开头那串） | 住独栋，**有正式门牌号**，别人能找上门 |
| **N 机** | 窝在运营商大内网里 | 住集体宿舍，**没门牌号**——只能它出去找人，别人进不来 |

由此得出本测试唯一要理解的规则：

> **N 主动找 V，V 见招拆招。**

V 想回信给 N，可 N 没有门牌号怎么办？不用愁——N 发来的第一个数据包上
自带"邮戳"（它从哪个出口出来的），V 照着邮戳回就行。工具里这个功能叫
`--learn-peer`，原理就这么简单，**你不用懂它，照命令敲就行**。

**开测前唯一的硬性前提**：N 机也得摸得到 IPv6 网络。
在 N 机上敲 `ping -6 baidu.com`——
✅ 有回复 = 能开测；❌ 不通 = 这台机器纯 IPv4，此方案走不通（先找网管开 IPv6）。

---

# 开测：每台机器三步

**第 1 步**：把 `ipv8-cross-verify.zip`（就 2 MB）拷到两台电脑，各自随便解压到哪个文件夹。

**第 2 步**：在 **V 机**上查自己的 IPv6 地址：
按 `Win+R` 输入 `cmd` 回车，敲 `ipconfig`，找 **IPv6 地址**那行，
要 `2` 开头的（`fe80` 开头的不要），整串复制下来。

**第 3 步**：两台机器各开一条命令（右键 PowerShell「以管理员身份运行」，
或者直接跑、弹窗点"是"）。

**V 机先跑**（把 `2xxxx::xxx` 换成 V 机自己刚查的那串 v6 地址）：

```powershell
powershell -File .\verify-cross.ps1 -Role B -PeerIp 2xxxx::xxx -LearnPeer
```

**N 机再跑**（`-PeerIp` 后面填的是**V 机**那串地址，不是自己的）：

```powershell
powershell -File .\verify-cross.ps1 -Role A -PeerIp 2xxxx::xxx
```

---

# 怎么算成功？

两台电脑的屏幕最后都会打一行字：

```
RESULT: PASS   ← 过了
RESULT: FAIL   ← 没过
```

**两台都 PASS = 这次跨真实网络的验证就成了。**
（判据不是"看着像通"，是隧道引擎肚子里四个计数器：发了多少、收了多少、
丢没丢包，全对账才算 PASS，糊弄不了。）

PASS 之后顺手还能看到一行 `TTL=` 开头的 ping 回包——两台真电脑之间一来一回
的实测延迟，这是以前"自己跟自己玩"永远拿不到的证据。

跑完脚本自动打扫战场，不往电脑里留任何垃圾文件。想留着日志慢慢看，
命令后面加 `-Keep`。

# 想测得更狠一点（可选开关，两台必须加一样的）

| 开关 | 加了它在测什么（一句话） |
|---|---|
| `-Fragment` | 硬塞 3000 字节的大包，逼隧道现场拆包→传输→复原，测"拆包重组"真功夫 |
| `-Zone -ZoneHost B` | 证书不再预先塞给两边，而是现场从 V 机的发证中心在线申请，测最真实的领证流程 |

# 安全软件死活拦着不让装网卡？用这个模式（-NoTun）

有些机器（尤其装了 360/火绒的）就是不给"创建虚拟网卡"放行——`Failed to create
adapter` 说的就是这事。别去想办法伪装程序骗过杀毒（那是病毒干的，而且人家拦的是
"凭空造网卡"这个动作本身，你换成什么皮它都照样拦，还把你这套正经工具带成可疑对象）。
**正路是：换一条根本不需要装网卡的路测。**

给两台机器的命令各加 `-NoTun`：

```powershell
# V 机（应答方）：
powershell -File .\verify-cross.ps1 -Role B -PeerIp <V机v6地址> -LearnPeer -NoTun
# N 机（发起方）：
powershell -File .\verify-cross.ps1 -Role A -PeerIp <V机v6地址> -NoTun
```

这个模式下：不加载 wintun、不建网卡、**连管理员都不用**（普通权限直接跑）。
改成程序自己造测试数据包，走真实 UDP 从一台发到另一台，对面原样加密弹回来，
发送方逐字节核对。**安全软件没东西可拦**，因为它压根没看到"装驱动"这个动作。

判成功的标志：屏幕打出 `[no-tun] ECHO_OK` 且最后 `RESULT: PASS`。

**⚠️ 说句实话，别自己骗自己**：这个模式验证的是隧道的**内核**——证书握手、
AEAD 加密解密、大包拆片重组，这些全在真实两台机器间跑通了，是硬证据。但它**没测
"和操作系统网卡对接"那一层**（因为故意绕开了）。不过那一层不用慌：你的开发机
（360 没拦的那台）上，同机双真实 wintun 网卡的测试**早就 PASS 记在案了**。
两块证据拼起来 = 完整链路成立。想连网卡层也在真机上证，就把这台机器加进白名单、
或用没装拦截软件的干净机器，去掉 `-NoTun` 再跑一遍。

一句话：`-NoTun` 是"躲开拦路的墙"，不是"骗过看门的"——堂堂正正，测的东西也真。

# 没过怎么办？先让 doctor 给你体检

在**失败的那台机器**上跑一条命令（跟 verify-cross 同一个文件夹里）：

```powershell
powershell -File .\doctor.ps1
```

它把 4 个常见病因挨个查一遍，`[FAIL]` 的后面直接写着怎么办。实测下来
"Failed to create adapter"（建虚拟网卡失败）九成是这三种：

| 病因 | 大白话 | 解法 |
|---|---|---|
| 权限是假的 | 你是管理员没错，但 UAC 把"创建网卡"这项能力滤掉了 | **右键 PowerShell →「以管理员身份运行」**，在这个窗口里再跑 verify-cross（弹窗点"是"后子进程仍是过滤令牌的情况，个别机器存在，手动管理窗口最稳） |
| 安全软件拦截 | 360/火绒之类把"凭空造一张网卡"当恶意行为 | 临时退出安全软件，或把解压文件夹加白名单后重试 |
| 旧驱动占坑 | 装过别的 VPN（WireGuard/WARP/Tailscale），留了张 2021 年的旧 wintun 驱动跟新驱动打架 | 先卸载那些 VPN；顽固的话管理员运行 `pnputil /enum-drivers` 找到 wintun 那条，用 `pnputil /delete-driver oemXX.inf /uninstall` 拔掉再试 |

都治不好？新版 `ipv8-node.exe` 会把失败原因的错误码直接打在报错行里，
（格式如 `Failed to create adapter [Win32 5 (0x5)]`），对照：

| 错误码 | 意思 | 解法 |
|---|---|---|
| `Win32 5` | 权限实际没生效（UAC 过滤令牌作祟） | 用「以管理员身份运行」的 PowerShell 窗口直接跑命令，别再依赖自动弹框 |
| `Win32 315` | 驱动被安全策略拉黑 | 360/杀软加白名单；或系统开了"智能应用控制"需关闭 |
| `Win32 110` | 已有一张被禁用的 Wintun 网卡 | 设备管理器 → 网络适配器 → 右键 Wintun → 启用设备 |
| `Win32 193` | wintun.dll 位数不对 | 确认解压的是 64 位系统、包完整没解漏 |
| 无任何码 | 老版本 exe | 你拿的不是最新 zip，重传一份 |

把这行带码报错发我也够定位。

## 其他对号入座

| 现象 | 十有八九是 | 怎么办 |
|---|---|---|
| V 机等不到任何帧 | N 机根本到不了 v6 网络 | 回 N 机重测 `ping -6 baidu.com` |
| 两台都转圈超时 | 防火墙/杀软拦了 | 脚本已自动放行，若装了第三方杀软，让它放行 UDP 45700 |
| 一台 PASS 一台 FAIL | 两台加的开关不一样 | 检查 `-Fragment`/`-Zone`/`-LearnPeer` 是否按上文配齐 |
| 报缺 wintun.dll | 解压没解全 | exe 和 dll 必须在同一个文件夹 |
| 想看细节 | — | 屏幕会告诉你日志文件在哪，打开即看（已自动折进结果文件） |

# 万一两台机器真在同一局域网

（比如都连同一个 WiFi）那更简单，不用现学：
两台互敲 `-Role A -PeerIp 对方的内网IP` / `-Role B -PeerIp 对方的内网IP` 即可。
